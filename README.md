## 🚴 快速开始

### 环境要求
- Python 3.8+
- NodeJS 18+

### 安装步骤
```bash
1. 克隆仓库
git clone https://github.com/shaxiu/XianyuAutoAgent.git
cd xianyu-autoagent

2. 安装依赖
pip install -r requirements.txt

3. 配置环境变量
创建一个 `.env` 文件，包含以下内容：
OPENAI_API_KEY=your_api_key_here
COOKIES_STR=your_cookies_here

4. 创建提示词文件prompts/*_prompt.txt
默认提供四个模板，可自行修改
```

### 使用方法

运行主程序：
```bash
python main.py
```

### 自定义提示词

可以通过编辑 `prompts` 目录下的文件来自定义各个专家的提示词：

- `classify_prompt.txt`: 意图分类提示词
- `price_prompt.txt`: 价格专家提示词
- `tech_prompt.txt`: 技术专家提示词
- `default_prompt.txt`: 默认回复提示词

### 配置 AI 模型

默认情况下，本项目统一使用在 `XianyuAgent.py` 文件中指定的 AI 模型。当前默认模型为： `deepseek/deepseek-chat-v3-0324:free` (通过 OpenRouter 调用)。

**如何修改默认 AI 模型:**

1.  打开 `XianyuAgent.py` 文件。
2.  找到 `XianyuReplyBot` 类的定义 (大约在文件开头部分)。
3.  在 `__init__` 方法内，找到这一行：
    ```python
    self.default_model = "deepseek/deepseek-chat-v3-0324:free"
    ```
4.  将引号内的模型名称替换为您想使用的其他 OpenRouter 模型标识符。
5.  保存文件并重新启动程序 (`python main.py`)。

**注意:** 此修改会改变所有 Agent (分类、价格、技术、默认) 使用的模型。如果需要为不同 Agent 指定不同模型，需要进一步修改 `XianyuAgent.py` 中的代码逻辑。

    *   AI应直接基于知识库中关于Claude 4.0（如FAQ C7，说明助手不支持该模型）及其他相关模型（如FAQ C9，说明支持Claude 3.7 Sonnet等）的信息进行回复，**避免不必要的反问**。

### 2. 强化产品形态说明，避免"提供账号"的误解 (YYYY-MM-DD)
*   **背景与问题**：AI客服在解释服务性质时，有时可能使用户误以为平台会直接提供一个"Cursor Pro账号"，而不是一个"登录助手软件的激活码"。这与产品的实际形态和价值主张不符。
*   **解决方案**：
    *   针对 `prompts/default_prompt.txt` (规则4) 和 `prompts/tech_prompt.txt` (规则4) 中的【重要核心规则 - 必须严格遵守】部分，对"产品形态澄清与强调"的规则进行了细化和强化。
    *   **核心要求**：
        1.  AI在回应此类询问时，【必须首先清晰地否定】这不是给用户自己的账号充值或升级，也【不是直接给用户一个独立的Cursor Pro账号】。
        2.  紧接着，【必须强调】提供的是【登录助手软件的激活码】。
        3.  并【简要解释】：用户通过激活码激活【登录助手软件】后，是这个【软件工具】来辅助用户在Cursor编辑器中登录并使用AI功能的。
        4.  最终让用户理解他们获得的是一个**工具的激活权限**，而不是一个账号本身。
*   **预期效果**：确保AI客服能准确、一致地传达产品的核心价值——即提供一个高性价比的【工具激活码】来辅助登录和使用Cursor AI功能，管理用户预期，避免因产品形态理解偏差导致的不满。

### 3. 修正"多设备使用"问题的错误回答，确保信息准确 (YYYY-MM-DD)
*   **背景与问题**：AI客服在用户问及"激活码是否支持多设备使用"时，曾错误地回答为"只能单设备使用"，这与知识库FAQ C6中明确说明"激活码支持在多台设备上激活和使用，并且可以同时在线"的核心事实相悖。
*   **解决方案**：
    *   经核查，知识库 `prompts/cursor_knowledge_base.txt` 中的FAQ C6关于多设备使用的说明是清晰且正确的。
    *   为确保AI严格遵循此FAQ，在 `prompts/default_prompt.txt` (新增为规则9) 和 `prompts/tech_prompt.txt` (新增为规则8) 的【重要核心规则 - 必须严格遵守】部分，均增补了一条高度针对性的规则：`【多设备使用问题的精准回答 - 严格依据C6】`。
    *   **该规则强制要求**：

        2.  【必须清晰告知操作】：换新设备时，无需登出旧设备，直接在新设备上使用同一激活码激活登录助手即可。
        3.  【避免任何暗示性的否定或不确定】：严禁回答为"只能单设备"，或在用户未明确报告问题前就优先引导至复杂的故障排除流程。
*   **预期效果**：AI客服能够准确、自信地回应所有关于多设备使用的咨询，直接传达产品支持多设备使用的便利性，消除用户疑虑，提升整体服务质量和用户满意度。

# 部署闲鱼自动回复机器人到宝塔面板 (VPS)

本文档记录了将此项目部署到安装了宝塔面板的 VPS 服务器上，并实现自动运行的详细步骤。

## 1. 环境准备

在开始之前，请确保您的 VPS 和宝塔面板已完成以下准备工作：

1.  **安装 Python 版本**:
    *   登录宝塔面板。
    *   进入 "软件商店" -> "运行环境"。
    *   找到 "Python 项目管理器"（新版可能直接在"网站"菜单下找到"Python项目"）。
    *   如果未安装，请安装。如果使用新版，请直接进入 "网站" -> "Python项目"。
    *   在 Python 版本管理中，安装一个合适的 Python 版本（例如 **3.10+**，我们之前使用的是 **3.13.3**）。

2.  **安装 Node.js**:
    *   进入 "软件商店" -> "运行环境" 或 "系统工具"。
    *   找到 "**Node.js 版本管理器**" 并安装。
    *   打开 Node.js 版本管理器，安装一个**稳定版本**（例如 **v18.x** 或 **v20.x**）。
    *   **关键步骤**: 安装完成后，务必在该管理器中找到您安装的版本，并点击 "**设置命令行版本**" 或类似的选项（如 "设为默认"），确保系统环境能够找到 `node` 命令。
    *   **(验证)**: 通过 **标准 SSH 客户端** (非宝塔内嵌终端) 连接服务器，运行 `node -v`，应该能看到版本号。

## 2. 上传项目文件

1.  登录宝塔面板。
2.  进入 "文件" 管理。
3.  在 `/www/wwwroot/` 目录下创建一个新的文件夹，例如 `xianyu-bot`。
4.  将您本地**完整**的项目文件和文件夹上传到 `/www/wwwroot/xianyu-bot/` 目录下。**确保包含**: `main.py`, `XianyuAgent.py`, `XianyuApis.py`, `context_manager.py`, `utils/` 目录, `prompts/` 目录, 以及 **`static/` 目录 (及其中的 `.js` 文件)**。

## 3. 创建并配置宝塔 Python 项目

1.  进入 "网站" -> "Python项目"。
2.  点击 "添加Python项目"。
3.  填写配置信息：
    *   **项目名称**: `xianyu-bot` (或其他您喜欢的名字)
    *   **项目端口**: `6666` (或任意未使用的端口，仅用于满足宝塔要求，项目本身不用此端口)
    *   **Python版本**: 选择您之前安装的版本 (例如 3.13.3)
    *   **启动方式**: **命令行启动**
    *   **项目路径**: `/www/wwwroot/xianyu-bot` (选择您上传文件的目录)
    *   **启动命令**: **`/www/server/pyporject_evn/xianyu-bot_venv/bin/python main.py`** (请将 `xianyu-bot_venv` 替换为您项目的实际虚拟环境名称，通常是 `项目名_venv`；路径也可能因宝塔版本略有不同，请检查确认)
    *   **启动用户**: `root` (推荐，以避免权限问题)
    *   **通讯协议**: wsgi (随便选一个)
4.  点击 "提交" 创建项目。

## 4. 配置环境变量

项目创建成功后，需要设置必要的环境变量：

1.  进入 "网站" -> "Python项目"，找到 `xianyu-bot` 项目。
2.  点击右侧的 "设置"。
3.  切换到 "**环境**" 选项卡。
4.  添加以下两个环境变量：
    *   名称: `COOKIES_STR`, 值: `您的闲鱼Cookies完整字符串`
    *   名称: `OPENROUTER_API_KEY`, 值: `您的OpenRouter API Key`
5.  **(备选方案：使用 .env 文件)** 您也可以在 `/www/wwwroot/xianyu-bot/` 目录下创建一个名为 `.env` 的文本文件，内容如下：
    ```env
    COOKIES_STR=您的闲鱼Cookies完整字符串
    OPENROUTER_API_KEY=您的OpenRouter API Key
    ```
    如果使用 `.env` 文件，请确保 `main.py` 或相关代码能正确加载它 (通常需要 `python-dotenv` 库和 `load_dotenv()` 函数)。宝塔的环境变量设置通常更直接。

## 5. 安装 Python 依赖库

1.  在项目 "设置" 页面，切换到 "**模块**" 选项卡。
2.  使用 "pip 命令" 或 "安装模块" 功能，安装以下所有必需的库：
    *   `openai`
    *   `loguru`
    *   `python-dotenv`
    *   `websockets`
    *   `watchdog`
    *   `PyExecJS`
3.  观察安装过程，确保没有报错。

## 6. 启动并验证项目

1.  **确保本地实例已停止**：如果您本地电脑上也在运行此项目，请先停止它，避免账号冲突。
2.  **启动项目**：回到宝塔 "Python项目" 列表，点击 `xianyu-bot` 右侧的 "**启动**" 按钮。
3.  **观察状态**：等待几秒，看状态是否变为 "**运行中**"。
4.  **检查日志**：立即点击项目右侧的 "**日志**" 按钮查看。
    *   正常的日志应该显示连接 WebSocket、心跳信息等，没有报错。
    *   常见的错误日志路径：`/www/wwwlogs/python/xianyu-bot/error.log` (请将 `xianyu-bot` 替换为您的项目名)。
5.  **功能测试**：用另一个闲鱼账号给您的店铺发送消息，看是否收到自动回复。

## 7. 配置自动运行与守护

1.  在项目 "设置" 页面，找到 "**启动管理**" 或相关选项。
2.  勾选 "**开机自启**"。
3.  检查并根据需要配置 "**进程守护**" 相关设置（例如异常退出时自动重启）。

## 8. 常见问题与排查

*   **`ModuleNotFoundError: No module named 'xxx'`**: 缺少 Python 库。
    *   **解决方案**: 请回到步骤 5，在项目的 **虚拟环境** 中安装缺失的库 `xxx`。可以通过宝塔模块管理安装，或通过 SSH 执行： `/www/server/pyporject_evn/xianyu-bot_venv/bin/pip install xxx` (注意替换路径和库名)。

*   **`FileNotFoundError: ... static/xianyu_js_version_2.js`** (或其他文件):
    *   **原因**: 项目依赖的文件（如 `.js` 文件、`prompts` 文件等）或其所在的目录（如 `static/`）未正确上传到项目路径 (`/www/wwwroot/xianyu-bot/`)。
    *   **排查**: 通过 SSH 运行 `ls -la /www/wwwroot/xianyu-bot/` 和 `ls -la /www/wwwroot/xianyu-bot/static/` (或其他相关路径) 检查文件/目录是否存在。
    *   **解决方案**: 请回到步骤 2，检查并重新上传缺失的文件或目录，确保目录结构完整。

*   **`execjs._exceptions.RuntimeUnavailableError: Could not find an available JavaScript runtime.`**: 未安装 Node.js 或 Python 无法找到它。
    *   **解决方案 1 (首选)**: 请回到步骤 1.2，确保 Node.js 已在宝塔 "Node.js 版本管理器" 中安装，并且 **关键步骤** 是点击了 "**设置命令行版本**" (或类似按钮)。
    *   **解决方案 2 (验证)**: 通过 **标准 SSH 客户端** (非宝塔内嵌终端) 连接服务器，运行 `node -v` 确认 Node.js 是否在系统 `PATH` 中。如果 SSH 中能找到但在宝塔启动时找不到，可能需要重启宝塔服务 (`bt restart`) 或重启服务器 (`reboot`)。
    *   **解决方案 3 (备选)**: 如果问题持续存在，可以考虑创建并使用 `start.sh` 启动脚本（见步骤 5 的备选方案），在脚本中明确指定 Node.js 的路径到 `PATH` 环境变量。

*   **`IndentationError` / `SyntaxError`**: Python 代码本身有语法错误。
    *   **原因**: 通常是代码缩进不正确，或者有其他不符合 Python 语法的地方。
    *   **解决方案**: 根据错误提示的文件名和行号，在**本地**仔细检查并修复代码。修复后，重新上传修改后的文件到服务器，覆盖旧文件，然后重启项目。
    *   **(谨慎操作)**: 对于简单的缩进或语法错误，也可以直接通过宝塔文件编辑或 SSH `nano` 编辑器修改服务器上的文件，但建议本地修复后上传。

*   **项目状态一直是"未启动"或启动失败**:

*   **定位与处理**：作为AI客服获取事实信息的基础，此文件**未进行大规模风格化修改**。其核心作用是提供准确、结构化的产品知识、价格信息和FAQ。AI客服的"年轻老板"风格主要由上述三个 prompt 文件在调用知识库信息并生成回复时赋予。此举旨在保证知识库信息的稳定性和准确性，便于维护，同时确保AI能基于可靠事实进行风格化表达。

通过上述调整，期望AI客服能在不同交互场景下，更一致地展现出符合预期的年轻化、接地气的沟通风格，从而更好地连接用户，提升整体服务感知。

本部分记录了近期为提升AI客服回复准确性和用户体验所做的一系列FAQ增补和prompt逻辑优化，方便后续借鉴与迭代。

2.  **FAQ增补与优化：解答"是否需要下载软件"并强调价值 (A5)**
    *   **背景**：用户常问及是否需要下载软件才能使用服务。
    *   **解决方案**：
        *   在 `prompts/cursor_knowledge_base.txt` 的FAQ A类（安装与激活问题）末尾增补了 `A5` 条目。
        *   `A5` 明确指出用户需要下载【登录助手软件】以及【Cursor编辑器本身】，并引导用户查阅教程或知识库中的【使用方法】获取详细步骤。
        *   后续对 `A5` 的措辞进行了优化，将原先"要使用咱们这个便捷的Cursor体验服务"修改为"想以超低价格用上接近Pro版的Cursor强大功能"，更直接地突出产品核心价值。
    *   **效果**：AI客服能清晰、完整地回答此基础问题，并在第一时间传递产品的核心吸引力。

3.  **意图理解优化：处理对模糊版本号（如"4.0"）的查询**
    *   **背景**：当用户问及如"4.0能用吗？"这类可能指代AI模型版本或Cursor编辑器版本的模糊问题时，AI可能错误地理解为询问编辑器版本。
    *   **分析**：经查，知识库 (`prompts/cursor_knowledge_base.txt`) 中已有关于Claude 4.0模型不支持的明确说明 (FAQ `C7`)。因此，问题核心在于提升AI对用户意图的理解能力，而非补充知识。
    *   **解决方案**：
        *   修改了 `prompts/default_prompt.txt` （通用接待场景）和 `prompts/tech_prompt.txt` （技术支持场景）中的回复要求部分。
        *   加入了明确的指导性规则，要求AI在遇到模糊的数字版本号查询（如 "4.0", "4", "3.7"）时：
            1.  **优先考虑AI模型上下文**：若对话涉及AI功能、模型能力或对比，应首先从AI模型的角度理解，并参考知识库中的相关FAQ（例如 `C7` 关于Claude 4.0，`C9` 关于3.5/3.7）。
            2.  **不确定时主动澄清**：若用户意图不明确，AI应主动反问以澄清，例如："宝，您问的是AI模型版本（像Claude 4.0那种）还是Cursor编辑器本身的版本号呀？"
            3.  **编辑器版本判断时机**：仅当对话明确指向软件安装、更新、界面特性，或用户提及典型编辑器版本格式（如 "0.x.x"）时，才主要按编辑器版本来理解和回复。
    *   **预期效果**：经过此番优化，AI客服在处理此类模糊查询时，能更智能地判断用户意图，优先从AI模型角度解读，并基于知识库给出如"Claude 4暂不支持哦，支持Claude 3.7"这类准确且符合用户预期的回复（回复风格会遵循各prompt中定义的客服人设），从而有效避免答非所问，提升沟通效率和用户满意度。
